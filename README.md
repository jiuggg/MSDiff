# MS2-Diff: Multi-View Semantic and Structural Diffusion for API Recommendation

MS2-Diff is a diffusion-based API recommendation framework that leverages multi-view structural and semantic guidance signals to improve recommendation quality on both the ProgrammableWeb API (PWA) and HiGitHub API (HGA) datasets.

### Dataset Filtering Rules

Both datasets apply the same filtering criterion during preprocessing: only Mashups/Apps that invoke **at least 3 APIs** are retained, along with the APIs they reference. This ensures every entity in the training set has sufficient interaction history.

### Train / Validation / Test Split

Interactions are split **per Mashup/App** using an approximate **8:1:1** ratio. For each entity, at least 1 interaction is guaranteed in both the validation and test sets. The random seed is fixed at `42` for reproducibility.

## Preprocessing

Run the preprocessing scripts to generate all feature files from the raw JSON data.

### PWA Dataset

```bash
python preprocess_pwa.py
```

This script:
1. Loads `dataset1/PWA/mashupData.json` and `dataset1/PWA/apiData.json`
2. Filters Mashups with fewer than 3 API calls
3. Splits interactions into train/val/test (8:1:1 per Mashup)
4. Builds 4 multi-view feature tensors (see below)
5. Saves all outputs to `dataset1/PWA_processed/`

### HGA Dataset

```bash
python preprocess_hga.py
```

This script performs the same steps for the HGA dataset, saving outputs to `dataset1/HGA_processed/`.

> **Note:** Preprocessing requires the SBERT model and may take 10–30 minutes depending on hardware, as it encodes all Mashup/App and API descriptions.

## Multi-View Guidance Signal Construction

MS2-Diff uses 4 guidance branches, each providing a different structural or semantic view of the interaction graph.

### Branch 1 — User-User Structural (2-hop Path)

Captures co-usage patterns between Mashups/Apps via shared APIs.

- Computes `S_uu = R · R^T` where `R` is the binary interaction matrix
- Removes self-loops and applies row normalization
- Shape: `[num_users, num_users]`
- Files: `features_2hop_mashup_PWA.pt` / `features_app_app_structural_HGA.pt`

### Branch 2 — Item-Item Structural Contextual (3-hop Path)

Propagates user-user similarity back to the item space.

- Computes `S_ui = S_uu_normalized · R`
- Masks out already-interacted items
- Shape: `[num_users, num_items]`
- Files: `features_contextual_api_api_similarity_PWA.pt` / `features_contextual_api_api_structural_HGA.pt`

### Branch 3 — User-Item Semantic (SBERT)

Captures semantic affinity between Mashup/App descriptions and API descriptions.

- Encodes descriptions with `all-MiniLM-L6-v2` and computes cosine similarity
- Shape: `[num_users, num_items]`
- Files: `features_mashup_api_complementarity_PWA.pt` / `features_app_api_semantic_similarity_HGA.pt`

### Branch 4 — User-User Semantic (SBERT)

Captures textual similarity between Mashup/App descriptions.

- Encodes descriptions with `all-MiniLM-L6-v2` and computes pairwise cosine similarity
- Removes self-similarity (diagonal set to 0)
- Shape: `[num_users, num_users]`
- Files: `features_mashup_text_similarity_PWA.pt` / `features_app_app_text_similarity_HGA.pt`

## Key Hyperparameters

The table below lists the main hyperparameters used in the paper's experiments.

| Parameter | Flag | PWA | HGA | Description |
|---|---|---|---|---|
| Learning rate | `--lr` | `0.0001` | `0.0001` | AdamW optimizer learning rate |
| Weight decay | `--weight_decay` | `0.01` | `0.01` | L2 regularization |
| Batch size | `--batch_size` | `512` | `512` | Training batch size |
| Model dimension | `--d_model` | `256` | `256` | Attention branch hidden dimension |
| Intermediate dim | `--dim_inters` | `256` | `256` | Encoder projection dimension |
| Attention heads | `--num_heads` | `4` | `4` | Number of multi-head attention heads |
| Attention layers | `--num_layers` | `2` | `2` | Layers per attention branch |
| Embedding size | `--emb_size` | `128` | `128` | Timestep embedding dimension |
| Dropout | `--dropout` | `0.5` | `0.5` | Dropout rate |
| Diffusion steps | `--steps` | `100` | `100` | Total forward diffusion steps T |
| Noise scale | `--noise_scale` | `0.04` | `0.04` | Beta schedule scaling factor |
| Noise schedule | `--noise_schedule` | `linear` | `linear` | Beta schedule type |
| Mean type | `--mean_type` | `x0` | `x0` | Diffusion prediction target (x₀) |
| Fusion mode | `--fusion_mode` | `attention` | `attention` | Multi-view fusion mechanism |
| CFG dropout prob | `--drop_prob` | `0.1` | `0.1` | Classifier-free guidance training dropout |
| CFG scale | `--cfg_scale` | `1.5` | `1.5` | Guidance scale at inference |
| Max epochs | `--epochs` | `200` | `200` | Maximum training epochs |
| Early stop patience | — | `100` | `100` | Epochs without improvement before stopping |
| Evaluation metric | `--early_stop_metric` | `combined_four` | `combined_four` | Early stopping criterion |
| Top-N | `--topN` | `[10, 20, 50]` | `[10, 20, 50]` | Evaluation cutoffs |

## Training

### PWA Dataset

```bash
python main.py \
  --dataset_type PWA \
  --dataset_name PWA_processed \
  --processed_data_path ./dataset1/ \
  --lr 0.0001 \
  --weight_decay 0.01 \
  --batch_size 512 \
  --epochs 200 \
  --d_model 256 \
  --dim_inters 256 \
  --num_heads 4 \
  --num_layers 2 \
  --emb_size 128 \
  --dropout 0.5 \
  --steps 100 \
  --noise_scale 0.04 \
  --noise_schedule linear \
  --mean_type x0 \
  --fusion_mode attention \
  --drop_prob 0.1 \
  --cfg_scale 1.5 \
  --early_stop_metric combined_four \
  --topN "[10, 20, 50]" \
  --cuda \
  --gpu 0 \
  --log_name pwa_final_submission_model \
  --save_path ./saved_models/
```

### HGA Dataset

```bash
python main.py \

  --dataset_name HGA_processed \

  --lr 0.0001 \
  --weight_decay 0.01 \

  --epochs 200 \
  --d_model 256 \
  --dim_inters 256 \
  --num_heads 4 \
  --num_layers 2 \
  --emb_size 128 \
  --dropout 0.5 \
  --steps 100 \
  --noise_scale 0.04 \
  --noise_schedule linear \
  --mean_type x0 \
  --fusion_mode attention \
  --drop_prob 0.1 \
  --cfg_scale 1.5 \
  --early_stop_metric combined_four \

  --cuda \
```

### Training Output

- Training logs are saved to `logs/<log_name>_<dataset>_<timestamp>.log`
- The best model checkpoint is saved to `saved_models/<dataset>/<dataset_name>_model_<params>_best.pth`
- Evaluation is performed every 5 epochs on both the validation and test sets
- Early stopping triggers after 100 epochs without improvement on the combined metric

## Evaluation / Inference

To evaluate a saved model checkpoint without retraining:

```bash
python inference.py \
  --dataset_type PWA \
  --dataset_name PWA_processed \
  --processed_data_path ./dataset1/ \
  --model_load_path ./saved_models/PWA/<your_model_checkpoint>.pth \
  --d_model 256 \
  --dim_inters 256 \
  --num_heads 4 \
  --num_layers 2 \
  --emb_size 128 \
  --dropout 0.5 \
  --steps 100 \
  --noise_scale 0.04 \
  --mean_type x0 \
  --topN "[10, 20, 50]" \
  --cuda \
  --gpu 0
```

Replace `--dataset_type PWA` with `HGA` and update `--model_load_path` accordingly for the HGA dataset.

The script reports Precision, Recall, NDCG, and MRR at cutoffs @10, @20, and @50 for both the validation and test sets.
